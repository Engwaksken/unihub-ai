# Management API: authentication and wire conventions (normative)

Both `/cms` (the caller) and `/gateway` (the verifier) MUST implement exactly this. Cross-app tests cover it.

## Headers on every request
| Header | Value |
|---|---|
| `Authorization` | `Bearer <management token>`. Issued by `php artisan gateway:mgmt-token` on the gateway and shown once. The CMS stores it in env `GATEWAY_MGMT_TOKEN`. |
| `X-Actor-Assertion` | A compact JWS (see below), freshly signed for each request |
| `X-Request-Id` | A UUID generated by the CMS. Every gateway call made while handling one CMS page request may reuse it. The gateway does not require it to be unique. It correlates both audit logs. |
| `Idempotency-Key` | **Required** on POST, PATCH and PUT. Use a UUID. Reuse it when retrying the same logical action. |
| `Accept` | `application/json` |

## Actor assertion (compact JWS, EdDSA / Ed25519)
```
base64url(header) "." base64url(payload) "." base64url(signature)     (base64url WITHOUT padding)
header  = {"alg":"EdDSA","typ":"JWT","kid":"cms-1"}
payload = {
  "iss": "unihub-cms",
  "aud": "unihub-gateway-mgmt",
  "iat": <unix seconds>,
  "exp": <iat + 60 at most>,
  "jti": "<uuid, single use>",
  "sub": "<CMS user uuid>",
  "name": "<display name, for audit readability>",
  "roles": ["owner" | "ops_admin" | "project_manager" | "auditor", ...],
  "projects": ["<gateway project uuid>", ...],   // informational; the gateway ignores it
  "project_roles": {"<project uuid>": "project_manager" | "auditor", ...},  // REQUIRED, JSON object, {} when none
  "mfa": true
}
signature = sodium_crypto_sign_detached(base64url(header) . "." . base64url(payload), <CMS 64-byte secret key>)
```
- **Keys.** The CMS keeps a 64-byte libsodium secret key, base64-encoded, in a file named by env `CMS_ASSERTION_SECRET_KEY_PATH`, outside the webroot. `php artisan cms:assertion-keypair` generates it and prints the base64 public key. On the gateway, the public key (32 bytes, base64) goes in `<GATEWAY_SECRETS_PATH>/cms_assertion.pub`.
- **Gateway rejects with 401 `UNAUTHENTICATED`** on any of these:
  - bad signature or `alg` other than `EdDSA`
  - wrong `iss` or `aud`
  - `exp` in the past, or `exp - iat > 60`
  - `iat` more than 30 s in the future
  - a `jti` that was already used
  - `mfa !== true`
  - an unknown role
- The CMS must only sign assertions for authenticated users who have completed MFA. `project_roles` comes from the user's `project_memberships`.
- **How the gateway reads `project_roles` (revised 2026-11-26, CMS contract finding #1):**
  - Grants that cover **all** projects come from any role in `roles`. For example, `owner` gets everything, and `project_manager` can view models.
  - Grants limited to **assigned** projects are resolved per project, from `project_roles` only.
  - So a user who is project manager on A and auditor on B gets auditor rights, not project-manager rights, on B.
  - The gateway rejects the assertion with 401 if `project_roles` is any of these:
    - missing
    - a list rather than an object
    - maps a project to a global role
    - maps a project to a role that is not in `roles`
- On a project where the actor has some role but not the needed capability, the gateway returns 403. On a project where the actor has no role at all, it returns 404.

## Response envelope
- Single resource: `{"data": {...}}`
- List: `{"data": [...], "next_cursor": "<opaque>" | null}`. Query parameters are `limit` (max 100, default 25) and `cursor`.
- Key issue: `{"data": {...api key metadata...}, "secret": "uhk_live_..."}`. The response carries `Cache-Control: no-store`. The secret appears only in this response.
- Error: `{"error": {"code": "...", "message": "...", "details": {...}?}, "request_id": "..."}`
  - Validation errors: 422 `VALIDATION_FAILED`, with `details.fields = {field: [messages]}`
  - Out-of-scope or unknown resource: 404 `NOT_FOUND`
  - A capability the actor's role lacks: 403 `FORBIDDEN`
- Idempotent replay of the same `Idempotency-Key` with the same body returns the stored response. A different body returns 409 `IDEMPOTENCY_CONFLICT`. Key issuance cannot be replayed (409 `IDEMPOTENCY_REPLAY_UNAVAILABLE`).
- All timestamps are UTC ISO-8601 (`2026-11-26T09:00:00Z`). Display them in Africa/Kampala.

## Resource shapes used by the CMS (P1)
```jsonc
// Organization
{"id":"uuid","name":"Unihub Solutions","status":"active|archived","project_count":3,"created_at":"...","updated_at":"..."}
// Project
{"id":"uuid","organization":{"id":"uuid","name":"..."},"slug":"my-digital-diary","name":"My Digital Diary",
 "owner_ref":"...","contact_email":"...","environment":"staging|production","status":"active|disabled|archived",
 "daily_limit":100,"rpm_limit":5,"queue_limit":2,"allowed_tasks":["daily_plan"],
 "created_at":"...","updated_at":"..."}
```
Organization endpoints:
- `GET /organizations` with optional `status` and `q`
- `POST /organizations` with `{name}`
- `GET /organizations/{id}`
- `PATCH /organizations/{id}` with `{name?, status?}`

Project endpoints:
- `GET /projects` with optional `organization_id`, `status` and `q`
- `POST /projects` with the `ProjectCreate` body from `management-openapi.yaml`
- `GET /projects/{id}`
- `PATCH /projects/{id}` with the `ProjectPatch` body. Field permissions follow `docs/permissions.md`, and a field the actor may not change returns 403 `FORBIDDEN`.
  - `owner_ref` and `contact_email` may be sent as `null` to clear them.
  - Quota fields (`daily_limit`, `rpm_limit`, `queue_limit`) are rejected with 403 from any actor without `project.quota`, including on `POST /projects`.
